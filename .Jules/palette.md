## 2024-07-05 - Added id to inputs and for to labels
**Learning:** Existing EJS templates extensively used `<label>` elements without `for` attributes and `<input>` elements without `id` attributes. This pattern was consistent across login, register, and profile forms, making them difficult for screen reader users to navigate and reducing the clickable area for all users. Furthermore, secondary address inputs (e.g. 'Apt, suite, unit') frequently lacked any visible label.
**Action:** Always verify that every input element has a corresponding `id` and that its associated label references it via a `for` attribute. When a visual label is omitted by design, ensure the input has an `aria-label` attribute providing equivalent context (e.g., `aria-label="Address Line 2"`). Applied this to `login.ejs`, `register.ejs`, and `profile.ejs`.
